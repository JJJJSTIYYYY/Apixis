# 处理程序链上下文令牌

每个前台事件分发拥有一个 `HandlerChainToken`。该分发中的所有前台处理程序和继承的子任务共享同一个令牌。后台处理程序在没有该令牌的情况下运行。公共 `suspend_process()` API 保持不变。

## 职责

该令牌是一个数据记录，而不是信号量管理器。它包含：

| 字段 | 含义 |
| --- | --- |
| `semaphore` | 事件循环的共享容量信号量。 |
| `held` | 此链当前是否拥有一个许可。 |
| `closed` | 分发是否已结束，并且所有权不能再恢复。 |
| `resume_lock` | 序列化试图恢复同一许可的独立子任务。 |

消费者先取出事件并固定 handler 引用列表，再等待容量、创建令牌，并将其安装到分发任务的上下文中。等待容量期间暂停消费者，会一起保留事件和这份列表，重启时继续使用。它在任务创建后立即恢复自己的上下文。完成回调显式接收同一个令牌，因此即使任务在第一条指令之前被取消，也有已知的所有者。

`suspend_process()` 和完成回调直接操作信号量。该令牌没有获取、释放或生命周期方法。

## 挂起与恢复

1. 没有令牌时，或在其链已关闭后，挂起是空操作。
2. 外层挂起会清除其任务的上下文，并且仅当 `held` 为 true 时释放许可。释放和标记更新不包含 await。
3. 嵌套调用看不到令牌，既不释放也不获取。在挂起内部创建的任务也继承这个空上下文。
4. 退出时，外层挂起获取 `resume_lock`，检查共享标记，在需要时获取容量，并且仅在获取成功后设置 `held`。
5. 即使释放或恢复失败，其原始上下文也会被恢复。

在挂起之前创建的兄弟任务保留同一个令牌。因此它们的释放共享 `held` 标记，并且它们的恢复被序列化。第一个恢复的独立挂起分支恢复该链的许可；其他分支复用它。嵌套调用不参与该协调。

容量单位仍然是处理程序链，而不是单个 Python 任务。此机制不会单独调度或计数每个并行分支。等待另一个事件的代码仍必须挂起，并且发布必须使用 `post_event()`。

## 取消与完成

如果获取被取消，`held` 保持 false。分发完成会将令牌标记为已关闭，并且只释放它实际持有的许可。取消后没有无条件释放。

生命周期长于分发的子任务不能重新打开其链。如果该子任务已经在等待获取时分发关闭，则该子任务在获取完成时立即归还许可。该令牌不会取消或汇合分离任务；其创建者仍负责它们的生命周期。

## 行为测试

回归测试使用一个可用槽位来演练事件发布和处理程序执行，而不是断言令牌字段或信号量计数器：

- 嵌套和并行等待，包括异常情况，在继续之前恢复容量。
- 恢复期间的取消，包括重复取消，不允许其他事件处理程序超过配置的并发度。
- 后台处理程序和已完成链的子任务不能出借前台容量。
- 并行图节点可以通过实际事件钩子中断和恢复，无论是否设置中断超时。
- 分发完成不会发出异步回调错误。
